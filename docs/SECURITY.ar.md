[English](../.github/SECURITY.md) · **العربية**

ولجميع مستخدميه.

## 📣 كيف تُبلِغ عن ثغرة

> ⚠️ **من فضلك لا تفتح Issue عامًّا** لمشكلة أمنية — فهذا يعرّض كل المستخدمين للخطر.

### الطريقة المُوصى بها (خاصة ومُتابَعة)

1. **GitHub Security Advisories** (الأفضل):
   `https://github.com/kerolos-it2022/network-monitor/security/advisories/new` ← *Report a vulnerability*.
   وهذا يُبقي التواصل خاصًّا بالكامل.
2. **وإن تعذّر ذلك** (مثلًا لا تملك صلاحية فتح Advisory): افتح Issue **بعنوان عام فقط** («طلب قناة تواصل
   أمني») **وبلا أي تفصيل تقني**، وسنردّ عليك بقناة خاصة.

### 🧾 ما يجب تضمينه في التقرير

- وصف المشكلة ونوعها (XSS · SQL Injection · SSRF · IDOR…).
- خطوات إعادة الإنتاج بالتفصيل (أو PoC).
- الإصدار المتأثّر.
- الأثر المتوقّع ودرجة الخطورة (مثل CVSS).
- أي اقتراح للإصلاح.

### أوقات الاستجابة المتوقّعة

| المرحلة | الوقت |
|---|---|
| 📥 تأكيد الاستلام | خلال 48 ساعة |
| 🔍 تقييم أولي وتوجيه | خلال 5 أيام عمل |
| 🛠️ الإصلاح + الإفصاح المنسَّق | حسب الخطورة (الجدول أدناه) |

| خطورة الثغرة | مهلة الإصلاح المستهدفة |
|---|---|
| حرجة (Critical) | خلال 7 أيام |
| عالية (High) | خلال 14 يومًا |
| متوسطة (Medium) | خلال 30 يومًا |
| منخفضة (Low) | في الإصدار المخطَّط التالي |

## ✅ الإفصاح المنسَّق

نلتزم بالإفصاح المسؤول:

- نستهدف إصلاح الثغرة قبل أي إعلان عام.
- ننشر **GitHub Security Advisory** بعد الإصلاح ليعرف المستخدمون نقطة التصحيح.
- نمنح المُبلِّغ فضل الإبلاغ في الإفصاح العام لو رغب.
- لن نلاحق الباحثين حسني النية الذين يتبعون هذه السياسة (Safe Harbour).

---

## 🛡️ أولويات قصوى

نرجو الاهتمام الفوري بأي ثغرة تمسّ:

- **سرية أو سلامة الجلسات** (`SESSION_SECRET` وكوكيز الجلسة).
- **تخزين أو إفصاح كلمات المرور** (تجزئات bcrypt · `DEFAULT_ADMIN_PASSWORD`).
- **حقن SQL** على أي مسار من مسارات الـAPI.
- **تجاوز المصادقة أو الصلاحيات** (تخطّي فحص الجلسة أو الدور).
- **تنفيذ كود عن بُعد** — عبر مسارات التحديث، أو عبر مساعدات root في الأبلاينس وملفات الطلب الخاصة بها
  (وقاعدة التصميم: خدمة الويب لا تستطيع تمرير أمر ولا مسار — وسم فقط أو أمر من قائمة بيضاء).
- **تسريب `.env`** أو اعتمادات طرف ثالث (تلجرام · واتساب · VAPID · توكن GitHub).

---

## 🧪 الاختبار الآمن

- استخدم **بيئة معزولة** (VM أو WSL جديد) — ولا بيانات إنتاج ولا أجهزة حقيقية.
- لا توجّه أدوات الشبكة (ping / tracert / scan) إلى أجهزة خارج نطاقك.
- قراءة الكود والخادم متوقّف (`backend/src/`) مشجَّعة قبل أي تشغيل.
