# 🏗️ المعمارية

[English](ARCHITECTURE.md) · **العربية**

كيف تتركّب أجزاء النظام، وأهم مسارات البيانات، ونموذج الأمان — بما يكفي للعمل على الكود أو لفهم أي نشر.

## شكل النظام

**وحدات متماسكة في عملية واحدة (modular monolith)**: عملية Node.js واحدة تقدّم REST API وبثّ SSE
والصفحات الثابتة والتقارير المطبوعة، وتتحدّث مع قاعدة SQLite محلية واحدة. لا يوجد طابور، ولا خدمة ثانية
تُدار، ولا خطوة بناء للواجهة.

```
المتصفح ──HTTP/SSE──► nginx (اختياري) ──► node (Express) ──► better-sqlite3 ──► monitoring.db
                                             │
                                             ├── محرك الفحص (ping/HTTP/HTTPS/TCP)
                                             ├── مستمع الاكتشاف (NBNS/mDNS/LLMNR/SSDP)
                                             ├── الإشعارات (تلجرام / واتساب / Web Push)
                                             ├── حلقات خلفية (الجدولة · التقرير اليومي · التصعيد ·
                                             │   حراسة المحرك · التنظيف · النسخ الاحتياطي)
                                             └── مساعدات root على الأبلاينس (nm-update · nm-remote)
```

## الخادم (backend)

| المسار | المسؤولية |
|---|---|
| `src/server.js` | الإقلاع: البيئة، قاعدة البيانات، الحلقات الخلفية، مستمع HTTP |
| `src/app.js` | تجميع Express، الجلسات، الصفحات الثابتة، تركيب المسارات، و`/api/health` (يقرأ الإصدار من `package.json`) |
| `src/db.js` | اتصال `better-sqlite3` متزامن واحد (WAL) + **هجرات آمنة** تُطبَّق عند الإقلاع |
| `src/routes/*` | طبقة HTTP رقيقة لكل مجال: auth · devices · locations · device-types · map · topology · live (SSE) · notifications · tools · update · appliance-update · backup · ai · system |
| `src/services/*` | السلوك الفعلي: محرك المراقبة، الفاحصون، الأعطال وRCA، السجل والنِسَب، الاكتشاف، الإشعارات، التنبيهات الذكية، التصعيد، جدولة المسح، نوافذ الصيانة، النسخ الاحتياطي، VAPID/Web Push، ngrok، مزامنة كلمة مرور الكونسول |
| `src/middleware/*` | الجلسات، الأدوار، حارس CSRF، سجل التدقيق |
| `test/*` | اختبارات `node:test` (١٦٩ اختبارًا): سلوك الـAPI · الأمان · الهجرات · تكافؤ الترجمة · الإشعارات · السجل · الحدود |

عادات مهمّة في الكود:

- **اتصال قاعدة واحد متزامن.** الاستعلامات تُحضَّر مرة وتُنفَّذ تزامنيًّا؛ لا يوجد pool ولا مشغّل غير متزامن
  — لذا تُقطَّع الحلقات الطويلة إلى دفعات صغيرة.
- **الهجرات إضافية وقابلة للتكرار** (`ALTER TABLE` محروس بفحص) فقاعدة قائمة تنجو من الترقية بلا خطوات يدوية.
- **الحلقات الخلفية مؤقّتات `.unref()`** تملكها الخدمات وتُشغَّل من `server.js`، فيستطيع الاختبار استيراد
  خدمة بلا تشغيل المحرك.
- **عملية الويب لا تنفّذ أوامر بصلاحيات root إطلاقًا** — أي شيء يحتاج root يُفوَّض لسكربت مساعد عبر
  **ملف طلب** (انظر قسم الأبلاينس).

## محرك الفحص والبيانات اللحظية

1. كل جهاز يحمل فاصله وحدّ فشله (`check_interval_seconds` · `failure_threshold`) وأحد البروتوكولات
   `ping | port | http | https`.
2. المحرك ينفّذ فحص كل جهاز في موعده، بحدٍّ أقصى `NM_MAX_CONCURRENT_CHECKS` متزامنًا.
3. تغيّر الحالة يكتب نقطة في `status_logs` ويُحدِّث `devices.current_status` ويفتح/يغلق حدثًا في
   `downtime_events`، وللخدمات يُحدِّث صحّتها المستقلّة التي تُنتج حالة `DEGRADED`.
4. كل تغيير يُنشر إلى **ناقل SSE** (`/api/live/status`) الذي يرسل لقطة للعميل الجديد ثم التغييرات فقط.
   والصفحة العامة وشاشة NOC ترجعان تلقائيًّا إلى polling لو فشل SSE.
5. **حلقة حراسة** تراقب المحرك نفسه (نبضه والفحوص العالقة) وتُصدر إنذارًا خاصًّا لو توقّف عن التقدّم —
   فلا تُعرض بيانات قديمة كأنها لحظية.

## الأعطال (RCA) ونِسَب التشغيل

- عند انقطاع جهاز ينظر المحرك في سلسلة الشبكة (`parent_id`) ويسأل: هل يشرح جهاز أعلى هذا الانقطاع؟ لو
  نعم يُسجَّل **عطل مركزي** واحد باسم السبب وقائمة المتأثرين، ويُرسل تنبيه واحد بدل رسالة لكل جهاز — مع
  بقاء سجل انقطاع مستقل لكل جهاز.
- نسبة التشغيل موزونة زمنيًّا على المدى المطلوب (24 ساعة / 7 أيام / 30 يومًا) وتُعرَض معها **تغطية** النافذة
  (كم من الوقت فيه بيانات فعلًا)، وتُجمَّع في ملخّصات ٩٠ يومًا قبل تنظيف سجلات `status_logs` الخام.

## الاكتشاف

مستمع دائم (NBNS · mDNS · LLMNR · SSDP) يجمع الأسماء التي يعلنها كل جهاز عن نفسه ويخزّنها في
`discovery_names`؛ ثم تضيف المسحات المجدولة أو الفورية نتائج ping/المنافذ وصانع MAC والـDNS العكسي والنوع
المقترح. ولا شيء يُضاف تلقائيًّا: النتائج تدخل **سلة اعتماد**، والمالك يختار، وقائمة الثقة تُسكِت المعروف
غير المرغوب.

## الإشعارات

`notifier.service` هو الكاتب الوحيد في `notification_logs`. القنوات (تلجرام · واتساب · Web Push) مستقلة،
وكل محاولة تُسجَّل: `sent` أو `failed` (بسبب المزوّد نفسه) أو `maintenance` (مكتوم بنافذة صيانة). والتنبيهات
الذكية تضيف تجميع العواصف والتقرير اليومي وتذكير التصعيد وبوت تلجرام التفاعلي. وملخّص الـAI لا يُطلب إلا
بوجود مفتاح، والعناوين الداخلية تُنقَّح قبل أن يخرج أي شيء من الجهاز.

## الواجهة

جافاسكربت خام (ES5/ES2018) بلا إطار عمل وبلا أدوات بناء. `ui.css` هي طبقة التصميم المشتركة فوق ملفات كل
صفحة؛ وملفات `nm-*.js` تحمل الاهتمامات المشتركة (التنسيق · الترجمة · زرّ اللغة) وملفات `admin-*.js` لكل
تبويب في اللوحة ملف. واللوحة ملف HTML واحد تُظهَر أقسامه وتُخفى عبر خريطة تبويبات، وبعض التبويبات تُظهر
أكثر من قسم. و`sw.js` ينفّذ كاش الـPWA واستقبال الإشعارات.

## نموذج الأمان

| الاهتمام | الأسلوب |
|---|---|
| الجلسات | `express-session` + كوكي httpOnly + سرّ عشوائي طويل + مخزن دائم + عمر افتراضي 12 ساعة |
| الأدوار | `admin` و`viewer`؛ مسارات الكتابة للمدير، وسجل التدقيق يوثّق من غيّر ماذا |
| CSRF | حارس على المسارات المتغيّرة + كوكيز SameSite |
| المدخلات | Prepared Statements في كل مكان؛ والمسارات العامة تُعيد **نسخة منقّاة** (بلا جرد داخلي، والعناوين للمسجّلين فقط) |
| الأسرار | في `backend/.env` فقط، ومقنّعة في الواجهة، ومفاتيح VAPID تولّدها الخدمة وتخزّنها بنفسها |
| الأبلاينس | تحصين systemd (`ProtectSystem=strict` · `NoNewPrivileges` · `PrivateTmp`) ومسار كتابة واحد، وnftables تسمح بـ80/443 فقط، وSSH معطّل، والمساعدات تُنادى عبر ملف طلب بقائمة بيضاء |

## الأبلاينس والتحديث الذاتي

على الأبلاينس المثبَّت تعمل خدمة الويب بمستخدم `netmon`، وهي **لا تستطيع الكتابة في كودها**: اللوحة تكتب
ملف طلب (يحوي وسمًا أو أمر وصول عن بُعد من قائمة بيضاء)، فتلاحظه وحدة systemd `.path` وتُشغّل الخدمة
الجذرية المقابلة التي تنزّل أرشيف الإصدار وتعمل `rsync` للـملفات و`npm ci` وتعيد تشغيل الخدمة. وNode
يُرقّى من نفس المسار عند الحاجة (`nm-node-upgrade`). وقائمة الكونسول (`nm-console`) واللوحة تتشاركان كلمة
مرور واحدة عبر `nm-sync-console-password`، بوصول من سطر واحد مقيَّد في `sudoers.d`.
